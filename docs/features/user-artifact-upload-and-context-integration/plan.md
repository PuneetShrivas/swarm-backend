# Feature: User Artifact Upload & Swarm Context Integration

**Datetime:** 2026-10-29T19:18:30+05:30  
**Status:** In Review (Awaiting User Approval)

## Goal

Enable users to upload artifacts (PDF, DOCX, PPTX, XLSX, CSV, JSON, Markdown, Code, TXT) across the platform, seamlessly invoke and attach them in chat conversations, grant swarm agents full contextual utilization and RAG retrieval over user artifacts, and empower users to upload or attach context files directly to workflow steps and custom agents during creation and editing.

## Scope

- In scope:
  - User artifact uploading in Artifacts Studio (`/artifacts`) with drag-and-drop and file browser for all supported document types (binary Base64 and text).
  - Automatic RAG knowledge indexing upon artifact creation, upload, and deletion.
  - "Invoke in Chat" action on artifacts in Artifacts Studio for immediate conversational navigation.
  - Direct file upload and artifact attachment right from the chat input screen (`ChatInput.tsx`, `chat/page.tsx`), with active context chips and drag-and-drop.
  - Multi-agent context utilization: Injecting attached artifact contents and grounded RAG citations into LLM prompts (Groq, Perplexity, Gemini) across all swarm agents.
  - Agent tooling: `inspect_artifact` and `search_artifacts` tools for dynamic agent artifact access.
  - Workflow step integration: Attaching artifacts and uploading files directly into workflow steps (`StepCardEditor.tsx`, `KnowledgeBaseManager.tsx`, backend execution engine).
  - Custom agent integration: Attaching knowledge artifacts and context documents during custom agent creation/editing (`AgentEditorModal.tsx`, backend custom agent endpoints).
  - End-to-end automated tests in `backend/test_endpoints.py` and frontend production build verification.
- Out of scope:
  - Third-party cloud drive sync (Google Drive, Dropbox) - local device upload and internal studio repository only.

## Current Behavior

1. **Artifacts Studio (`/artifacts`)**: Users can only view, download, copy, and delete artifacts that were generated by agents or workflows. There is no file upload button or manual creation interface for users to introduce external documents into their artifact library.
2. **Chat Input (`ChatInput.tsx`)**: Only handles text prompts and slash commands (`/workflows`, `/agents`, `/clear`). Users cannot attach existing artifacts or upload documents directly from the chat screen.
3. **Agent Context**: Swarm agents only receive the raw user prompt and chat history. They cannot directly access or ground their answers in user artifacts unless pasted manually as text.
4. **Workflow Steps & Custom Agents**: Workflow knowledge files can only be uploaded as raw plain text via `reader.readAsText` and cannot import existing artifacts from Artifacts Studio. Custom agents only have name, role, description, and system prompt without attached domain knowledge artifacts.

## Proposed Behavior

1. **User Artifact Upload in Studio (`/artifacts`)**:
   - "Upload Artifact" button and drag-and-drop dropzone.
   - Supports binary files (PDF, DOCX, PPTX, XLSX) via Base64 encoding and text files (CSV, JSON, Markdown, Code, TXT).
   - Automatically computes metadata, MIME type, and indexes into the Swarm `RAGKnowledgeStore` via `ingest_and_index_document`.
   - "Invoke in Chat" button on cards to start a conversation grounded on that artifact.

2. **Chat Screen Upload & Artifact Invocation (`ChatInput.tsx`, `chat/page.tsx`)**:
   - Paperclip/Plus button in `ChatInput` with:
     - "Upload Context File": direct native file picker and drag-and-drop to upload and immediately attach as active context.
     - "Attach from Artifacts": modal picker showing all user artifacts with instant search and selection.
   - Active context chips above the textarea with file icons, size, and dismiss button (`[x]`).
   - Attached artifact IDs sent in `ChatRequest` to `/api/chat`.

3. **Swarm Agent Context Utilization (`backend/app/main.py`)**:
   - `/api/chat` extracts attached artifacts, formats a structured `[Attached User Artifacts & Knowledge Context]` markdown block, and injects it into system prompt / turn context.
   - Grounded context is passed whether running Groq Qwen, Perplexity Sonar, or Gemini models.
   - Swarm agents have access to `inspect_artifact` and `search_artifacts` tools.

4. **Workflow Steps & Custom Agent Context Integration**:
   - In `StepCardEditor.tsx` & `KnowledgeBaseManager.tsx`: Add "Attach from Artifacts" and "Upload Context File" directly to workflow step knowledge configuration, enabling binary uploads and studio artifact imports.
   - In `execute_workflow_step` and step unit testing: Inject attached knowledge files and artifacts into step prompt context.
   - In `AgentEditorModal.tsx`: Add an "Attached Knowledge Artifacts" selector for custom agents.
   - In `CustomAgentCreate` & `CustomAgentUpdate`: Persist `attached_artifact_ids` and inject into custom agent system prompts during chat and testing.

  artifact_ids?: string[];

// Artifact Payload Extension
interface ArtifactCreatePayload {

  filename: string;

  size_bytes?: number;

  mime_type?: string;

  source_type?: string;

## Risks and Mitigations

| Risk | Impact | Mitigation |
| ---- | ------ | ---------- |
| Large uploaded binary files bloating chat prompt | Token limit exceeded or latency spike | Truncate raw context or use RAG hybrid retrieval to extract only top relevant chunks |
| Binary Base64 vs text file mishandling | Corrupted artifact downloads | Auto-detect extension and MIME type; use Base64 only for binary (`pdf`, `docx`, `pptx`, `xlsx`), UTF-8 text for scripts/data |
| Serverless instance cache misses | Context lost across instances | Persist artifact index to temporary storage (`/tmp/swarm_rag_store.json`) and database |
